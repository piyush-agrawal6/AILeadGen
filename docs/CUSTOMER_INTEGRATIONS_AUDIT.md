# PlaneByte Intent Radar — customer integrations audit

**Post-audit local implementation:** The inventory and counts below are the historical baseline at `6b9c401`. The working checkout now includes shared Radar exports, a manual Sheets review flow and signed Radar events. See [implementation and acceptance evidence](INTENT_RADAR_EXPORTS_SHEETS_WEBHOOKS_IMPLEMENTATION.md) before using the historical card recommendations. No new production connection was verified.

**Decision:** Publish a directory of scoped capabilities, not a list of connected apps. The clearest working Radar actions are downloading discovery results, exporting completed Growth research, copying record links, and reading workspace records through the gated developer API. No CRM install flow was found. The generic webhook system cannot currently deliver the Radar event advertised by its card.

**Evidence boundary:** Read-only source inspection, 2026-11-21. ## H — Security and reliability gaps

1. **Availability vs authority:** `experience.tsx:20–25` renders the static directory before capability errors. A green badge can appear for a workspace with no entitlement or for a disabled backend. An admin role, enabled flag, issued key, and successful provider action are four different facts. Never infer connection health from any one of the first three.
2. **Workspace switching:** `dashboard/components/workspaces/integrations.tsx:15` uses the constant React Query key `['organization-integrations']`. Verify cache invalidation/isolation on switch before remounting that component. Server ownership checks are present; stale client metadata is a separate concern. No cross-tenant breach was established.
3. **Export integrity:** Discovery builds CSV using JSON string escaping and joins with commas (`InlineResultsPanel.tsx:583–594`); this is not a CSV writer and does not neutralize spreadsheet formula prefixes. Growth uses a real CSV writer and cell guard (`app/growth_intelligence/exports.py:6–18`). Share an export contract and test quotes, commas, newlines, formula-like text, retention, redaction, filtered totals and pagination. Do not imply CSV contains the complete workspace or that downloaded data can later be revoked.
4. **Consent/revocation:** Write access must not silently replace read-only Sheets access; Gmail scopes are broader than login. Label local disconnect honestly; offer provider-side revocation guidance. Rotation of the envelope key needs a tested rollover procedure. Callback URLs and refreshed credentials must never appear in logs or catalog state.
5. **Delivery:** Webhook deduplication on enqueue does not guarantee a downstream write happened once. Keep stable event IDs, consumer deduplication, retention checks and visible terminal failures. Validate periodic dispatch independently of endpoint creation. No healthy production webhook schedule, customer Gmail schedule, digest generator or named MCP client was established.
6. **Data minimization and diagnostics:** Webhooks emit IDs rather than arbitrary record payloads; keep that boundary for Radar topics. `app/notifications/center.py:752–756` can return a truncated exception string on a test delivery error; review redaction. `ResearchLibraryWorkspace.tsx:271–294` combines static conclusions with excerpts—avoid exporting it as a verified research finding. These are review findings, not observed incidents.
